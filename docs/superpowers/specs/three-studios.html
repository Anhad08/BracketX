Three Studios

The same screen, three ways. Each is a complete point of view rather than a colour change — pick one and the whole product follows from it. The graphic on the stage is identical in all three, because that belongs to the broadcaster and is never ours to restyle.

Gallery A · where it is now

An instrument for a dark room. Matte surfaces, hairline rules, nothing raised that is not pressable, and colour reserved so completely that the only saturated thing on screen is what is on air.

Type

System sans for reading, mono for every number a person compares — timecode, duration, dimensions. Six sizes, tracking bound to each.

What it buys

  • Survives a twelve-hour shift without eye fatigue
  • On-air state is unmistakable at 40% brightness from two metres
  • Dense — an operator sees everything without scrolling
  • Cheapest to reach: it is largely built

What it costs

  • Reads as a developer tool to a newcomer
  • Little warmth — hard to make a marketing screenshot sing
  • Restraint can tip into flat if spacing is not perfect

Studio Glass B · Apple-influenced

The graphic is the ground truth and the interface floats above it. Chrome becomes translucent material — blurred, layered, with the work visible through it — and everything moves on springs that can be grabbed mid-flight and thrown back.

Motion

Springs, not durations. Critically damped by default (no overshoot); bounce only where a gesture carried momentum. Every panel is interruptible — grab a closing dock and it follows your pointer instead of finishing first.

What it buys

  • Feels current and premium — the direction that photographs best
  • Depth does the explaining: what floats is chrome, what is flat is the work
  • Panels can overlap the stage without hiding it

What it costs

  • Broadcast graphics are transparent. Glass over glass is the one stack that destroys legibility
  • backdrop-filter alongside four live WebGL contexts is a real frame-budget risk
  • Softer contrast is worse in a bright gallery
  • Largest build: springs and gestures are engineering, not CSS

Console C · hardware

The product looks like the desk it replaces. Machined edges, keys that sit proud of the surface and depress when struck, engraved labels, and a tally lamp that is a lamp. An operator who has run a vision mixer knows where everything is before reading a word.

Type

Mono throughout, engraved-small and wide-tracked — the legend on a piece of equipment, not a document. Values in tabular figures so a changing score never shifts width.

What it buys

  • Unmistakable — nobody would confuse it with a generic web app
  • Every control reads as pressable; targets are naturally large
  • Maps to hardware an operator already knows
  • Strongest fit for the rundown-and-hotkeys desk that is still to build

What it costs

  • Skeuomorphism ages badly if pushed past restraint
  • Chunky controls mean less on screen at once
  • Bevels and inner shadows are easy to get subtly wrong

How to choose

Not on taste alone — each direction implies a different product. If the buyer is a broadcaster's engineering department, A is what they expect and it is nearly built. If it is a streamer choosing between this and a consumer tool, B is the one that wins a demo. If the thing you are selling is that this replaces a physical desk, C says so before anyone reads the copy.

They are also not exclusive at every layer. The honest hybrid is A for the working surfaces and C for the air controls — quiet where a designer spends hours, tactile where an operator commits. B is the one that must be taken whole: half-glass reads as a bug.
