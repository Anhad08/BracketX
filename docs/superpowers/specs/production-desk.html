The Production Desk

Studio airs one graphic at a time. To run a show it needs four channels, a rundown, and keys an operator's hands can find without looking.

Background Lower · On air Upper · Cued Overlay Impossible today

01The problem

ProgramBus holds one preview session and one program session, and take() is program.open(document) — it replaces whatever was on air. A lower third and a ticker cannot both be out. There is no rundown: what comes next lives in the operator's head. There are no numbered keys and no panic. production.tsx is a scrolling page whose monitors sit below the fold, under the live-data and check blocks.

This is a missing capability, not a layout. Conformance check C8 — no control exists for a capability the engine lacks — means the engine work leads and the interface follows.

A second problem arrived with it: measured against the product's own Design OS, the Design screen fails several checks outright. Type sizes below the six-step scale, which is what truncated an easing label to easir. No single primary action. Undesigned empty and error states. And Depth — the beginner/expert split — exists in workspace.ts and is unreachable from the UI, so neither audience gets what it was built for.

02Decomposition

Five sub-projects, each with its own plan and its own verification. Production precedes Design deliberately: Design's problems are conformance problems with known fixes, and Production's are missing capability. Capability takes longer to be wrong about.

03Foundation

Two workspaces, named for the task rather than the person. Nobody wants to be labelled a beginner by their own tool. Depth keeps its type name and its two values; only its expression changes.

Catalogue, edges— no switch —

Three rules make it work:

  • Visible. A segmented control in the header, in the same screen position in every section. The current failure isn't that the levels are wrong — it's that they're unreachable.
  • The right position is a superset. Switching never removes a control that was in use, and shared controls don't move. Fields that jump make a switch feel unsafe to press.
  • Reversible in one key, both directions. ⌥E, already bound.
Risk accepted A switch whose labels change per section is a switch the operator re-reads. The alternative is one neutral pair used product-wide, at the cost of the task-naming. Ship the section-specific labels; revisit if it confuses anyone.

Conformance becomes a test

A Playwright pass walks computed styles across every section and fails on any spacing or type value outside the scale. A design system that cannot fail a review is decoration — Volume One says so, and this is what saying so costs.

04Channels

ProgramBus stops owning one program session and starts owning several. Each channel is a full StudioSession with its own host, mirror and clock — the same argument program.ts already makes for separating Preview from Program, applied one level further. One runtime cannot be at two frames, and two graphics on air are at two frames.

Four, named by broadcast role rather than numbered, because an operator says kill the ticker and not kill layer three.

z 0background — sting, full-frame bedOff
z 1lower — name strap, score bugOn air
z 2upper — ticker, breaking bandOff
z 3overlay — countdown, clockOff
export type ChannelId = "background" | "lower" | "upper" | "overlay";

export class ProgramBus {
  readonly preview: StudioSession;

  /** Builds the channel's session on first use. */
  channel(id: ChannelId): Channel;
  /** Channels with frames going out, in compositing order. */
  get live(): readonly ChannelId[];
  /** True when ANY channel is on air. Drives tally and ducking. */
  get onAir(): boolean;

  cue(id: ChannelId): TakeResult;
  take(id: ChannelId, mode?: TakeMode): TakeResult;
  clear(id: ChannelId): void;
  clearAll(): void;
}
  • Lazily constructed. A channel's session isn't built until something is taken to it. An operator running one lower third pays for one session.
  • No default channel. Every call names its target. A defaulting API is how everything quietly lands on one layer and the feature appears not to work.
  • Show-level state stays on the bus. A show that put thirty-four graphics out across four channels ran from its first take to going off air. clearAll() stamps the end; clear(id) doesn't.
Context budget Four channels + preview + the hover player = six WebGL contexts, against a browser ceiling near sixteen. The codebase has already met that ceiling once — the Marketplace hover player exists because forty contexts do not work — so the budget is stated here rather than discovered later.

05The rundown

An ordered list of items; an item is a graphic, plus tonight's values, plus where it goes. 

export interface RundownItem {
  readonly id: string;
  readonly name: string;
  readonly source:
    | { readonly kind: "template";  readonly templateId: string }
    | { readonly kind: "document";  readonly json: string };
  readonly channel: ChannelId;
  /** Tonight's values. Overrides, never document edits. */
  readonly data: Readonly<Record<string, string | number>>;
  /** 1–9, or null. */
  readonly hotkey: number | null;
}

It lives in studio/rundown.ts as its own saveable document, and not in the scene format. program.ts already refuses to put role: "entrance" in the format on the grounds that the engine would have to understand a product concept forever. A rundown is a larger version of the same noun and gets the same answer.

Item state — ready, cued, live, done — is derived from channel state and never stored on the item. Two answers to “what is on air” is how the wrong one comes to be believed.

06Hotkeys

CommandBindingWhy
air.cueItem.1 … .91 – 9Cue the numbered item.
air.takeNextCtrl / ⌘ + EnterPlain Enter belongs to the focused control — commit af9e138 deliberately gave it back. Space pans the viewport.
air.clearAllShift + EscA chord one hand cannot strike by accident, executing instantly once struck.

Active only in Production at the Desk level, and never while a text field has focus. 1–9 are ordinary characters everywhere else, and a binding that swallows typing is worse than no binding.

Air is not undoable, so the guard on panic belongs in the gesture, not in a confirmation dialog — C5 forbids delaying a consequential action behind animation, and a modal is worse than an animation.

07The desk

A fixed grid. Regions that can overflow — the rundown list, the live-data column — scroll internally. Nothing an operator needs is ever below the fold, which is the specific failure of the current page.

The channel strip is one cell per layer, each with its own clear, so the ticker can be dropped without touching the score. Program is drawn larger than Preview: they are not equals, and the one going out should look like it.

Preflight keeps its role, moving from a block in the scroll to a state on the cued item — an operator wants “this one has a problem” attached to the thing, not filed under a heading.

08How it's proven

The test that matters Cue item 3 by hotkey, take it, and assert by pixel readback that two graphics are on air simultaneously. Everything else in P1 can pass while the feature does not work. This cannot.
  • Unit — channels. Taking to lower leaves upper's canonical hash untouched. Clearing one channel leaves the others live. Cue is refused on a channel already on air.
  • Unit — rundown. Ordering survives a round trip. A corrupt stored rundown loads as empty rather than throwing.
  • E2E — panic. Shift+Esc from three live channels leaves all four off air and the tally reading OFF.
  • Performance. Four live sessions measured on the low-end device profile before the UI commits to offering four.

09Risks

Blocker · not ours to land The render-order fix that multi-layer compositing relies on sits uncommitted in the working tree at three-backend.ts:392, alongside leftover debug instrumentation at lines 394–408 that logs on every mesh attach. A console.log on that path during a four-channel show is a performance defect in its own right. This belongs to another session and must land before P1 can be verified.
  • Four mirrors is four mirrors. If the low-end profile can't hold four live channels at frame budget, the answer is fewer channels offered on that profile — not a slower show.
  • Scope. P1 and P2 together are the bulk of this work and considerably larger than the request that started it. P3 and P4 shouldn't be planned until P2 is in.

10Conformance

This page is built under the checklist it describes. The rules are the product's, not the page's.

  • C1Every spacing value is one of nine, on a 4pt grid.
  • C2Every type size is one of six, with its tracking bound to it.
  • C3No semantic hue appears without its meaning. Red and amber appear only where something is genuinely on air or genuinely cued — never as decoration. They are the only saturated values in the document.
  • C5Nothing with consequence is delayed by animation.
  • C9It survives the gallery test: at 40% brightness from two metres, on-air state is unmistakable and nothing else is.
  • C10It survives the twelve-hour test. Nothing loops, nothing pulses, nothing moves in peripheral vision. There is no ambient motion on this page, by rule.
